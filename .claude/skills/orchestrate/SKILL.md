# Orchestrate

You are the **orchestrator**. Work through the `ready-for-agent` tickets one at a time, with no user in the loop. For each ticket a subagent implements it, opens its PR, gets CI green and writes a retro. You merge the PR and compile the retro notes into one digest.

**Never ask the user anything** (no AskUserQuestion, no "want me to…?"). Every choice below has a default. Where none fits, take the conservative option and record it in the digest.

Arguments (optional): `max <N>` caps the tickets this run (default 10); a list of ticket numbers (`#68 #71`) restricts the run to them, in that order.

## Setup

1. Read `docs/agents/issue-tracker.md` and `docs/agents/triage-labels.md`.
2. Resolve the newest installed skills folder and keep the path as `SKILLS`:
   ```bash
   ls -d ~/.claude/plugins/cache/claude-plugins-official/mattpocock-skills/*/skills/engineering | sort -V | tail -1
   ```
   `implement` and `retro` set `disable-model-invocation`, so subagents read their `SKILL.md` instead of calling the Skill tool.
3. Make the run folder `retros/<YYYY-MM-DD-HHMM>/` at the root of the main checkout (git-ignored). Its absolute path is `RUN_DIR`.
4. **Resume first.** List open PRs whose head starts with `claude/mattpocock-skills-implement-` (`gh pr list --state open --json number,headRefName,isDraft,url`). Take each one that isn't a draft through **Merge** before starting new work. Drafts were handed off earlier: leave them.

## The loop

1. **Pick.** Run `python3 .claude/skills/orchestrate/frontier.py --why`. It prints the startable tickets oldest first (open, `ready-for-agent`, unassigned, no open sub-issues, no open blocker) and, on stderr, why the others were skipped. Take the first one, or the next one from the arguments that is startable. Recompute every time: a merge can unblock a ticket.
2. **Claim.** `gh issue edit <n> --add-assignee @me`.
3. **Spawn.** One Agent call, `subagent_type: general-purpose`, `isolation: worktree`, with the prompt under **Subagent prompt** filled in. Wait for it to finish. It ends with a `RESULT` block.
4. **Act on the result:** `STATUS: green` → **Merge**. `STATUS: handoff`, `STATUS: failed`, or no `RESULT` block → **Hand off**.
5. **Record** the outcome (merged or handed off, PR, one-line reason) in `RUN_DIR/outcomes.md`.

**Stop** when the frontier is empty, the cap is reached, or two tickets in a row ended `failed` (red CI after its fix rounds, or a subagent that crashed). A `handoff` for hardware or judgement doesn't count toward that: it says something about the ticket, not the setup. Then write the **Digest**.

### Merge

1. Confirm green yourself: `gh pr checks <pr> --required` shows every required check passing. If one is pending, wait with `gh pr checks <pr> --required --watch --interval 30` (Bash timeout 600000; run it again if the timeout ends it). If one failed, treat the ticket as `failed` and **Hand off**.
2. `gh pr merge <pr> --squash`. The repository deletes the branch on merge. Branch protection refuses a merge without green required checks, so a refusal means **Hand off**, not retry.
3. Confirm the ticket closed (`gh issue view <n> --json state`). If it didn't, close it with a comment linking the merged PR.
4. `git worktree remove <WORKTREE from RESULT>`. If git refuses (uncommitted files), leave it and note it in `outcomes.md`.

### Hand off

1. If a PR exists, make it a draft: `gh pr ready <pr> --undo`.
2. Comment on the ticket, starting with `> *This was generated by AI by the orchestrator.*`: what was done, what stopped it (the subagent's reason, or the failing check and its error), the PR link if any, and what a human needs to decide or do.
3. `gh issue edit <n> --remove-label ready-for-agent --add-label ready-for-human --remove-assignee @me`.

### Digest

Write `RUN_DIR/digest.md`:

- **Run:** date, `main` before and after, tickets merged (with PR links) and handed off (with reasons).
- **Findings:** every retro file in `RUN_DIR`, merged. Deduplicate findings several tickets raised and say how many raised each: a repeat is the strongest signal. Order by severity, grouped by the retro's categories (Navigation, Automated checks, Coding standards, Global AGENTS.md, Tool economy, No-ops, Information access). Link each finding to its PRs.
- Nothing in the digest is applied. It's for the maintainer to triage.

Then tell the user where the digest is in one short message with the counts, and send the file with SendUserFile.

## Subagent prompt

Fill in `<n>`, `<title>`, `<SKILLS>` and `<RUN_DIR>`:

````text
You are implementing GitHub issue #<n> ("<title>") in skolldev/cairn, unattended. Nobody will answer questions: never ask the user anything. Where the ticket leaves a choice open, take the most conservative reading of its agent brief and record the choice in the PR body.

You are in your own git worktree. Read CLAUDE.md and docs/agents/issue-tracker.md first.

0. Bail-out check, before writing code. Stop with STATUS: handoff if the ticket:
   - needs hardware or access you don't have (the physical Windows PC, a GitHub or Azure DevOps account, a person watching the screen, `scripts/budget.sh run`),
   - is already done in the codebase, or is a parent or handoff spec rather than one piece of work,
   - needs a design decision its brief doesn't make.
   Say which, with evidence.

1. Branch: `git fetch origin && git switch -c claude/mattpocock-skills-implement-<n> origin/main`.

2. Implement: read `<SKILLS>/implement/SKILL.md` and follow it for ticket #<n>. Its Skill-tool steps are callable as `mattpocock-skills:tdd` and `mattpocock-skills:code-review`. Before pushing, run the checks CODING_STANDARDS.md and CI expect; anything that runs git must pass on the oldest supported git (`scripts/oldest-git.sh`).

3. PR: push the branch, then call the Skill tool with `mattpocock-skills:pr` for the body. Title: "<title> (#<n>)". The body contains `Closes #<n>` and ends with the line `🤖 Generated with [Claude Code](https://claude.com/claude-code)`. Create it with `gh pr create --base main`. Don't merge it.

4. CI: `gh pr checks <pr> --required --watch --fail-fast --interval 30` (Bash timeout 600000; run it again if the timeout ends it). On a failure, read the failed job's log (`gh run view <run-id> --log-failed`), fix it on the branch and push. At most 2 fix rounds. A failure in code your change doesn't touch that passes on rerun (`gh run rerun <run-id> --failed`) is a flake: note it in the retro and don't count it as a fix round. Still red after 2 rounds: STATUS: failed.

5. Retro, whatever the status (skip only if you stopped at step 0 before any work): read `<SKILLS>/retro/SKILL.md` and follow it on this session. Instead of presenting the candidates to a user, write them to `<RUN_DIR>/<n>.md`, ordered by severity, each with its category, the evidence from this session, and the change you suggest. Don't apply any of them.

6. End your final message with exactly:
RESULT
STATUS: green | handoff | failed
PR: <url or none>
BRANCH: <branch or none>
WORKTREE: <absolute path of this worktree>
RETRO: <path or none>
REASON: <one line>
````
