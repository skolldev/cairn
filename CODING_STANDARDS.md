# Coding standards

Judgement calls a reviewer applies to every change. Rules a script can check live in `scripts/` and run in CI instead: GPUI only in `cairn-app` (`check-gpui-free.sh`), git spawned only by `cairn-write` (`check-single-git-spawn.sh`, which lets the Budget harness start `cairn` and PresentMon from one file that refuses git), one oldest git everywhere (`check-git-floor.sh`), and every gix pathspec anchored with `top` (`check-gix-pathspec-top.sh`). Domain terms come from `CONTEXT.md`; decisions from `docs/adr/`.

## Tests

From #14's testing decisions.

- **Seams.** A test drives the system through a public seam and asserts what a caller could observe. There are four seams:
  - **`cairn-repo`'s interface** (Intents in, Snapshots out) is the main one. Assert Snapshot contents, the order and generation of Snapshots, Job outcomes, git's error text, and the repository on disk afterwards. Its `read_job` and `external_change` tracing spans are part of it too, and a `publish` span inside a `read_job`: the Budget work learns where time goes from them (#40, #83), and a watcher test learns from an `external_change` span's `paths` which change started a refresh (#59). A test installs the subscriber in `crates/repo/tests/common/trace.rs` and matches spans by their repository, since other tests' services run in the same binary.
  - **`cairn-write`'s runner** (an `Invocation` in, `Output` or git's error out) is for rules awkward to reach through Intents.
  - **`cairn-app`'s window** (a close or click in; a prompt, an exit or the repository on disk out) is for what `app` decides. GPUI's `test-support` drives it, with the real Repo service and real git behind it, as `crates/app/src/quit/tests.rs` does. The test window draws only when resized, so the Bridge drains on its timer: advance the executor's clock.
  - **`cairn-budget`'s public interface** (samples and traces in, verdicts and reports out, and the sandbox a fixture is cloned into) is for how the Budget harness judges numbers. Worked examples, never the same formula again. What it can't show is real presentation timing, because test windows present nothing: that takes a harness run (`docs/budget-harness.md`).
- **Observable behaviour.** Tests stay out of the scheduler's queues, the runner's argument list and gix internals. When a runner rule needs proving, prove it through what git itself reports (`git config --get`, an `!env` alias, the index on disk).
- **Real git.** Tests run real git against real repositories. Where timing matters, control it through git's own extension points (hooks, a wrapper around `upload-pack`), never by injecting fakes into private modules.
- **Real filesystem events.** Each OS reports different events, so a watcher test passing on one says nothing about another: `docs/filesystem-events.md` lists what each reports. `scripts/linux-tests.sh` runs tests against inotify from a Mac.
- **Shared helpers.** Each library crate's `tests/common` holds the fixtures and harness its test files share (`Release`, `open`, `Seen`, the blocking hook). A new test file reuses them; a helper a second file needs moves there.
- **Hermetic config.** Tests run git with an empty user config and no system config, so a developer's `commit.gpgsign` or `core.longpaths` can't change the result. `crates/write/tests/common` shows the pattern: set `HOME`, `XDG_CONFIG_HOME` and `GIT_CONFIG_NOSYSTEM` once per test binary, before anything spawns git.
- **Oldest git.** Every test that runs git passes on the oldest supported git (`GitVersion::MINIMUM`): `cairn-write`'s, `cairn-repo`'s and `cairn-budget`'s in CI, and `cairn-app`'s locally, with its `measure` feature, because that Linux job doesn't build GPUI. Use only git features that it has, in product code and in tests: `docs/git-versions.md` lists what arrived later, and gates any assertion on a newer git's behaviour. Check with `scripts/git-matrix.sh`, which also runs the newest git released, as CI's macOS and Windows runners do.
- **One Slot per assertion.** Assert on the Snapshots of the Slot under test. Other Slots answer the same Intent on their own schedule, so "nothing more arrives" holds only per Slot.
- **Wait for the state, not the next Snapshot.** The watcher publishes too, after any change to the repository: a Job's midway writes, and the test's own git commands. Wait for the Snapshot that shows the expected state, as `a_fetch_streams_progress_and_ends_with_a_refs_only_refresh` waits for the fetched tip, rather than the first one newer than a generation.
- **git as the oracle.** Run oracle commands as a Read Job runs git (`JobClass::Read`, which adds `--no-optional-locks`). Otherwise `git status` refreshes the index on disk and erases a stat-dirty "before" state. Plumbing such as `git diff-files` never refreshes, so it lists stat-only changes that `git status` doesn't.
- **Controls.** A test that asserts something *didn't* happen pairs it with a control showing the setup would make it happen otherwise. `reads_never_take_the_index_lock` is the example.
- **Seen red.** A test that passed on its first run has never shown it can fail. Break the code it guards, watch it go red, and name that break in a comment beside the assertion. A test that went red before its code existed has shown it already, and needs no comment. The break must hit the branch the test actually runs: clones on macOS and Windows have `core.ignorecase=true` and Linux clones don't, so a break in one case mode's code stays green on the other OS. `scripts/seen-red.py` runs a break and restores the file. A diff can't show which is which, so the PR's Evidence lists the tests that passed first time. A diff that changes the code a Seen-red comment names runs that break again, and Evidence lists the result: a break that stays green means the test no longer guards it, so rework the test and its comment. `in_a_linked_worktree_a_newly_tracked_ignored_file_shows_in_unstaged_when_changed` stayed green this way after #35 started watching a linked worktree's index. `quick_refreshes_of_one_slot_publish_only_newer_generations_and_never_a_stopped_read` passed with its guard removed until each read was slowed.
- **Waiting for nothing.** Prove an absence through a later **marker**: an event that can only follow the unwanted one, such as the next Job in the same queue running (`network_jobs_run_one_at_a_time_and_a_queued_one_stops_without_starting`), or an outcome the unwanted event would have changed. Wait a fixed time only when nothing marks the absence, as with a refresh that must not be queued, and name that test's control in a comment beside the wait.
- **Flakes.** A test that fails now and then on code nobody changed gets a `flaky` issue. `scripts/flake-hunt.py` reproduces it locally, unattended, and says how many clean runs show a fix worked: `docs/flake-hunting.md`.
- **Benchmarks are not tests.** A criterion regression threshold is a CI signal. Budget measurements come from a local harness run before a phase gate: `scripts/budget.sh`, described in `docs/budget-harness.md`.
